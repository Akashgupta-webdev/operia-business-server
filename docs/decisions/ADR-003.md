# ADR-003: Use Rotating Cookie-Based JWT Sessions

- Status: Accepted
- Date: 2026-08-06
- Amended: 2026-08-12

## Context

Release 1 needs access-key login, expiring browser sessions, automatic renewal,
and credential protection. Authentication must not expose stored credentials or
tokens in response bodies and must reject inactive Users.

## Decision

Users authenticate with a generated, high-entropy access key containing at
least 32 characters. MongoDB stores its SHA-256 digest in `accessKey`, never the
raw value. A successful login issues a 15-minute access JWT and a seven-day
refresh JWT in `HttpOnly` cookies. Local development uses `SameSite=Strict`.
Production uses `SameSite=None; Secure` so the separately hosted HTTPS frontend
can make credentialed requests to the API.

Only a digest of the current refresh JWT is persisted. Every refresh rotates
the token and invalidates its predecessor. A new login replaces the current
refresh session, so Release 1 permits one refresh session per User. The session
endpoint renews both cookies when the access token is no longer usable and the
refresh token remains valid. Inactive Users cannot establish or renew sessions.

Signing secrets come from validated runtime configuration. Access and refresh
tokens use distinct secrets, fixed issuer and audience claims, explicit token
types, and the HS256 algorithm.

## Consequences

- Browser JavaScript cannot read authentication cookies.
- Refresh-token replay fails after successful rotation.
- A new login signs out the User's previously refreshable browser session.
- Access-token revocation takes effect at its short expiry; deactivation is
  checked whenever the session endpoint or refresh endpoint loads the User.
- Cross-site production cookies require an exact trusted frontend origin in the
  credentialed CORS allowlist. Wildcard origins are prohibited, and any new
  state-changing endpoint requires a CSRF review.

## Rejected Alternatives

- Plaintext stored access keys: exposes all credentials after a database leak.
- Long-lived access JWTs without refresh rotation: weak revocation behavior.
- Tokens returned to browser JavaScript: increases exposure to script-based
  credential theft.
