# Client API

## 1. Scope

This API supports direct creation of Client records by an authenticated Admin.
Lead conversion, duplicate matching, history migration, and links to Policies
or other deferred modules are not part of this endpoint.

## 2. Create Client

`POST /api/v1/clients`

Only an active User with the `ADMIN` role may call this endpoint.

The JSON request accepts:

| Field | Requirement |
| --- | --- |
| `name` | Required; 2 to 200 characters |
| `mobileNumber` | Optional; at least one contact field is required |
| `whatsappNumber` | Optional; at least one contact field is required |
| `emailAddress` | Optional valid email; at least one contact field is required |
| `nationality` | Optional; maximum 120 characters |
| `emiratesIdNumber` | Optional; maximum 30 characters |
| `passportNumber` | Optional; maximum 30 characters |
| `address` | Optional; maximum 500 characters |
| `preferredCommunicationMethod` | Required: `EMAIL`, `WHATSAPP`, or `CALL` |
| `notes` | Optional; maximum 5,000 characters |
| `clientStatus` | Optional: `ACTIVE`, `INACTIVE`, `PROSPECT`, or `ARCHIVED`; defaults to `ACTIVE` |

Unknown request fields are rejected. The Client type defaults to
`INDIVIDUAL` because this create contract does not currently expose
`clientType`.

Successful creation returns `201 Created`, a standard single-resource
response envelope, a `Location` header, and a version `ETag`.

## 3. Create Client with Service

`POST /api/v1/clients/with-service`

Only an active User with the `ADMIN` role may call this endpoint. The request
uses `multipart/form-data`:

| Part | Requirement |
| --- | --- |
| `payload` | Required JSON string containing the Client Service package |
| `documents` | Optional repeated file part; maximum 10 files and 10 MiB per file |

Cloudinary must be configured with `CLOUDINARY_URL`, or with all of
`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET`.

The `payload.client` object requires `clientType`, `name`, `mobileNumber`,
`whatsappNumber`, `emailAddress`, `nationality`, `passportNumber`,
`emiratesIdNumber`, and `preferredCommunicationMethod`. Existing optional
Client fields remain accepted.

For `client.clientType = INDIVIDUAL`, `payload.company` must be omitted. For
`client.clientType = COMPANY`, `payload.company` is required and must include
`companyName`, `companyType`, and `licence.number` plus `licence.expiryDate`.
Other documented Company fields are optional.

`payload.service` is required and contains `category`, `status`, and a
non-empty dynamic `detail` object. Client, Company, and Service identifiers are
generated by the server and must not appear in the payload.

`payload.payment` and `payload.reminder` are optional. When Payment is present,
all amount fields are required non-negative decimal strings so decimal
precision is retained. When Reminder is present, `dueDate`, `reminderBefore`,
and `followUpsDate` are required.

Example `payload` for an individual Client:

```json
{
  "client": {
    "clientType": "INDIVIDUAL",
    "name": "Example Person",
    "mobileNumber": "+971501234567",
    "whatsappNumber": "+971501234567",
    "emailAddress": "person@example.test",
    "nationality": "Emirati",
    "passportNumber": "P123456",
    "emiratesIdNumber": "784-0000-0000000-0",
    "preferredCommunicationMethod": "EMAIL"
  },
  "service": {
    "category": "VAT_REGISTRATION",
    "status": "NOT_STARTED",
    "detail": {
      "applicationType": "New"
    }
  }
}
```

Cloudinary uploads occur before persistence. Client, optional Company,
Service, Document metadata, optional Payment, and optional Reminder records
then commit in one MongoDB transaction. If upload or persistence fails, no
success is returned and uploaded Cloudinary assets are cleaned up.

Successful creation returns `201 Created`, a `Location` header for the Client,
an `ETag`, and:

```json
{
  "data": {
    "client": {},
    "company": null,
    "service": {},
    "documents": [],
    "payment": null,
    "reminder": null
  },
  "meta": {
    "correlationId": "opaque-correlation-id"
  }
}
```

## 4. Get Client Service Package

`GET /api/v1/clients/{clientId}/with-service/{serviceId}`

Only an active User with the `ADMIN` role may call this endpoint.

| Path parameter | Requirement |
| --- | --- |
| `clientId` | Required public Client identifier; 1 to 128 characters |
| `serviceId` | Required 24-character hexadecimal Service MongoDB `_id` |

The Service must belong to the requested Client. The endpoint returns the full
Client, optional Company, Service, every Document sorted by newest creation
time, the latest Payment by `paymentDate`, and the latest Reminder by creation
time. There are no query parameters or request body.

```json
{
  "data": {
    "client": {},
    "company": null,
    "service": {},
    "documents": [],
    "payment": null,
    "reminder": null
  },
  "meta": {
    "correlationId": "opaque-correlation-id"
  }
}
```

An unknown Client returns `404 CLIENT_NOT_FOUND`. An unknown Service, or a
Service that does not belong to the Client, returns
`404 CLIENT_SERVICE_NOT_FOUND`.

## 5. Get Client Summary

`GET /api/v1/clients/{clientId}`

Only an active User with the `ADMIN` role may call this endpoint. The
response returns only:

- `clientId`
- `name`
- `emiratesIdNumber`
- `emailAddress`
- `mobileNumber`
- `whatsappNumber`
- `clientStatus`

Optional values that are not recorded are returned as `null`. An unknown
Client identifier returns `404 CLIENT_NOT_FOUND`.

## 6. List Clients

`GET /api/v1/clients?page={page}&limit={limit}&search={search}`

Only an active User with the `ADMIN` role may call this endpoint.

| Query | Requirement |
| --- | --- |
| `page` | Optional positive integer; defaults to `1` |
| `limit` | Optional integer from `1` to `100`; defaults to `25` |
| `search` | Optional trimmed string from 1 to 100 characters |

Search is case-insensitive and matches Client name, Emirates ID number, email
address, mobile number, or WhatsApp number. Results are sorted by newest
creation time first with `clientId` as the deterministic tie-breaker.

Each result uses the same fields as the Client summary endpoint. The response
contains:

```json
{
  "data": [],
  "page": {
    "page": 1,
    "limit": 25,
    "total": 0,
    "totalPages": 0
  },
  "meta": {
    "correlationId": "opaque-correlation-id"
  }
}
```

An empty result returns `200` with an empty `data` array.

## 7. Errors

- `401 AUTHENTICATION_REQUIRED` when no valid session is available.
- `403 FORBIDDEN` when the authenticated User is not an Admin.
- `422 VALIDATION_FAILED` when the request does not satisfy the field rules.
- `404 CLIENT_NOT_FOUND` when the requested Client does not exist.
- `404 CLIENT_SERVICE_NOT_FOUND` when the requested Service does not exist for
  the Client.
- `500 INTERNAL_ERROR` for an unexpected persistence failure.
- `500 UPLOAD_CONFIGURATION_ERROR` when Cloudinary is not configured for an
  upload request.
